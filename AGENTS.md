# AGENTS.md

Instructions for AI agents (and humans) working in this repository. Follow them literally. When a rule and your
judgment disagree, the rule wins; ask the maintainer instead of deviating.

This repository is the **single public home for all NewsCatcher benchmarks**. NewsCatcher is one of the vendors
being benchmarked, so credibility is the product: every published number must be traceable, and nothing published
may be changed or removed afterwards.

## 1. Invariants (never break these)

| # | Rule | Why |
|---|---|---|
| 1 | One repository. Never create a repository per run, per suite or per quarter. | One URL, stars and history stay together; one place to fix bugs. |
| 2 | Never commit `runs/`, `data/`, `.env`, `*.sqlite`, or any `*.zip`. `.gitignore` blocks them; do not force-add. | `runs/` holds raw provider output including Exa's. `.env` holds keys. |
| 3 | Only the public cut is ever published: generated by `export.py --run <run> --public`. It has no Exa rows (Exa may appear only in `*_summary_by_system.csv` and `systems.csv`) and no snippet columns. | Exa's terms restrict redistribution; snippets belong to their publishers. |
| 4 | A published `results/<run>/` folder is immutable. Fix mistakes with an `## Errata` section in its README plus a `CHANGELOG.md` line. Never edit its tables, never delete it. | Deleting or quietly editing results destroys trust. |
| 5 | Every number in a run README comes from `scores.md` or the CSVs, copied by the script. Never type, round, estimate or "improve" a number. | Traceability. |
| 6 | Never run `run.py`, `judge.py`, or anything that calls a paid API unless the maintainer asked for a run in this session. | Cost: one run costs real money (see the suite README). |
| 7 | Never put API keys, tokens or `.env` content in a commit, issue, PR, log or message. | Security. |
| 8 | Do not edit a published run's `queries.json` snapshot or the suite's `queries.json` after a run used it. A new query set means a new run and a CHANGELOG entry. | Runs must stay reproducible. |

## 2. Layout

```
benchmarks/                          # repository root
├── README.md                        # suites, run index, how to reproduce
├── AGENTS.md  CLAUDE.md             # this file (CLAUDE.md just imports it)
├── DISCLOSURE.md  CHANGELOG.md  CITATION.cff  LICENSE  .env.example  .gitignore
├── scripts/publish_run.py           # the only supported way to publish a run; --check verifies
├── templates/run-readme.md          # README template filled by publish_run.py
├── .github/workflows/verify-public.yml
└── benchmarks/
    ├── s1-event-recall/             # one folder per suite; self-contained pipeline
    │   ├── README.md METHOD.md SYSTEMS.md DATA.md
    │   ├── queries.json             # frozen per run
    │   ├── run.py pool.py judge.py pagecheck.py score.py export.py
    │   ├── runs/<run>/              # LOCAL ONLY, gitignored: raw output, pools, labels, scores.md
    │   ├── data/<run>/              # LOCAL ONLY, gitignored: export.py output
    │   └── results/<run>/           # PUBLISHED, committed, immutable
    │       ├── README.md            # results, what changed, deviations, weaknesses, errata
    │       ├── scores.md  queries.json  MANIFEST.json
    │       └── s?_queries.csv  s?_summary_by_system.csv  s?_metrics_per_query_window.csv  systems.csv
    └── s2-everyday-search/          # same shape; shared helpers in lib/
```

| Path | Committed | Contains |
|---|---|---|
| `benchmarks/<suite>/results/<run>/` | yes | the small public tables, scores, manifest, run README |
| `benchmarks/<suite>/runs/`, `data/` | **no** | raw and full data; keep privately (outside this repo) |
| GitHub Release tagged `<suite>/<run>` | n/a | `<suite>_<run>_public-data.zip`: row-level public tables |
| `dist/` | **no** | staging for the Release zip |

## 3. Naming

| Thing | Convention | Example |
|---|---|---|
| Suite folder | `s<N>-<kebab-name>` | `s3-company-monitoring` |
| Run id | ISO date of the run start, as passed to `--run`; same string for `runs/`, `data/`, `results/` | `2026-11-24` |
| Results folder | `benchmarks/<suite>/results/<run id>/` | `benchmarks/s1-event-recall/results/2026-11-24/` |
| Git tag / Release | `<suite>/<run id>` | `s1-event-recall/2026-11-24` |
| Release asset | `<suite>_<run id>_public-data.zip` | `s1-event-recall_2026-11-24_public-data.zip` |
| Two runs on the same day | append a letter to the run id | `2026-11-24b` |

## 4. Decision matrix: what to do for each task

| Task | Do this | Do not |
|---|---|---|
| Publish a finished run | Section 5, all steps | Copy files by hand; skip `--check`; skip the Release |
| Run an existing suite again | Section 5 from step 1, new run id | Reuse an old run id; edit `queries.json` |
| Change the queries, judge model or prompt, windows, depth, or system settings | New run id. Update the suite's `METHOD.md`/`SYSTEMS.md`/`queries.json`. Add a CHANGELOG entry that says results are **not comparable** with earlier runs. State it in the new run README under "What changed". | Rerun an old id; present a changed method as a like-for-like trend |
| Add a provider/system | Add it in the suite's `run.py` (S2: `lib/clients.py`) and document endpoint, parameters and why in `SYSTEMS.md` (best setting from its own docs, no per-vendor query tuning). Needs a new run. Disclose in `DISCLOSURE.md` if it changes who is tested. | Tune a query for one vendor |
| Add a new suite | Create `benchmarks/s<N>-<name>/` with `README.md`, `METHOD.md`, `SYSTEMS.md`, `DATA.md`, `queries.json`, pipeline scripts and an empty `results/.gitkeep`. Keep scripts standard-library-only and path-relative (`HERE = Path(__file__).resolve().parent`, outputs in `HERE/runs` and `HERE/data`), so `publish_run.py` works unchanged. Add it to the root README suite table. | Create a new repo; write outside the suite folder |
| A published number is wrong | Add `## Errata` to that run's README: what was wrong, the corrected value, the date. Add a CHANGELOG line. If the data was wrong, publish a corrected **new** run and link both ways. | Edit tables in place; delete the run or the Release |
| Someone asks for raw data | Share only what is in the Release zip or `results/`. | Share `runs/`, any Exa row, any snippet |
| A file is over 5 MB | It goes in the Release zip, not in git. | Add Git LFS (it bills the repo owner per clone); commit the file |
| `--check` fails | Fix the cause. If the cause is Exa rows or snippets, re-run `export.py --public`. | Edit `FORBIDDEN_COLUMNS`/`EXA_*` in `publish_run.py` to make it pass |
| Duplicated code between suites | Leave it (section 7). | Refactor as a side effect of another task |

## 5. Procedure: publish a run

Run these in order. Stop at the first failure and report it.

| Step | Where | Command | Result |
|---|---|---|---|
| 1 | repo root | `cp .env.example .env`, fill keys, `set -a; . ./.env; set +a` | keys in the shell (skipped providers are skipped) |
| 2 | `benchmarks/<suite>/` | `python3 run.py --run <run>` | `runs/<run>/raw/...` |
| 3 | same | `python3 pool.py --run <run>` | blind pools |
| 4 | same | `python3 judge.py --run <run>` | labels (S1 and S2) |
| 5 | same, **S1 only** | `python3 pagecheck.py --run <run>` | real publication dates (S2 does this inside `pool.py`) |
| 6 | same | `python3 score.py --run <run> > runs/<run>/scores.md` | `scores.md` |
| 7 | same | `python3 export.py --run <run> --public` | `data/<run>/*.csv`, public cut. Do not use `--sqlite` for publishing. |
| 8 | repo root | `python3 scripts/publish_run.py --suite <suite> --run <run>` | `results/<run>/` and `dist/<zip>` |
| 9 | repo root | edit `benchmarks/<suite>/results/<run>/README.md`: replace every `TODO` | no `TODO` left |
| 10 | repo root | `python3 scripts/publish_run.py --check` | `ok` |
| 11 | repo root | `git add benchmarks/<suite>/results/<run> && git commit` | commit on a branch, PR to `main` |
| 12 | after merge | `gh release create <suite>/<run> dist/<zip> --title ... --notes ... --target main` | Release with the zip |
| 13 | repo root | add a row to "Published runs" in `README.md` (newest first) and an entry to `CHANGELOG.md` | index updated |

Back up `runs/<run>/` and the full (non-public) export privately, outside this repo, so the run can be re-scored
without re-spending API credits. Never in the Release.

## 6. Run README: what the maintainer must fill in (step 9)

| Section | Must contain |
|---|---|
| Header table | judge model and prompt version; first and last API call (UTC). Harness commit, queries hash, Release link and zip hash are filled by the script. |
| Results | already filled from `scores.md`. Add nothing to the numbers. Interpretation goes below, as plain sentences. |
| What changed since the previous run | every difference that affects comparability, or "First published run." |
| Deviations and failures | outages, timeouts, skipped systems, partial results, how `score.py` treated them |
| Known weaknesses | what favours or hurts any system, **including NewsCatcher's own weak spots**. Do not omit unfavourable findings. |
| Errata | `None.` until something is corrected |

## 7. Known issues (do not fix opportunistically)

| Issue | Status |
|---|---|

## 8. Pre-commit checklist

- [ ] `git status` shows nothing under `runs/`, `data/`, `dist/`, and no `.env` or `*.zip`.
- [ ] `python3 scripts/publish_run.py --check` prints `ok`.
- [ ] No published `results/<run>/` file other than `README.md` (Errata) was modified.
- [ ] `CHANGELOG.md` and the README "Published runs" table are updated.
- [ ] No secret appears in the diff.
